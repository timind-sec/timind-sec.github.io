前言

前一天看完h2database的jdbc，然后第二天总结的时候发现还有另外一种数据库也存在类似的RCE（最后发现根本不是一回事），那就是Pgsql的JDBC注入，但是我认为两者之间还是存在极大的不同的，h2有点类似mysql里面的UDF 提权需要通过INIT语句来创建恶意的命令执行函数，而Pgsql则是通过某个特定的类去加载外部的恶意xml并RCE，虽说都是JDBC，但本质还是有些区别的

接下来仅对本人的调试过程进行详细的复盘

环境搭建

在idea里边新建一个maven项目，然后编辑pom.xml

因为该RCE漏洞需要用到后续一个关键类ClassPathXmlApplicationContext，在Spring框架里边的一个类，所以这个攻击也暂时仅限于Spring框架中，剩下的Pgsql组件不必多说，依赖影响范围：9.4.1208 <=PgJDBC <42.2.25||42.3.0 <=PgJDBC < 42.3.2

PgsqlDemo.java

evil.xml

这样我们的环境就搭建完成了，可以愉快的调试了

调试分析

代码很少，我们找关键函数就行了，猜测漏洞触发点在getConnection处

DriverManager#getConnection里边还会调用到另外一个重写的getConnection方法，继续跟进

发现里边调用了connect方法，用于连接Pgsql，可以看看他进行了什么样的操作

跟进到调用connect方法的DriverManager类里面

前面一大堆基本上就是对jdbc:postgresql这样的url进行处理

随后调用了makeConnection方法，可以看看目前的栈信息

url就是我们前面传入的那一长串的jdbcURL，然后props是Properties实例化出来的一个对象

包含了Pgsql的数据库，端口以及后面的关键类socketFactory还有远程恶意xml

跟进看到makeConnection调用了PgConnection的构造方法，特别长

但是通篇看下来其实发现他主要的作用就是去和数据库服务器建立 TCP 连接，然后也可以操作一些sql语句。

然后漏洞调试的时候发现跟到PgConnection#openConnection()方法时有了新发现

跟进去看看

然后到了下一个转折点

到了一个接口类的一个方法openConnectionImpl

里边会调用一个getSocketFactory方法，类似获取Socket连接的函数

逐步跟进到ObjectFactory#instantiate

然后这里我们就可以看到，又是反射获取构造器之类的危险操作，这里我们可以具体看一下，然后方便调试的话也可以在public static Object instantiate旁边点上个小红点，这样每次运行的时候就会到我们想要分析的地方了，同时我们也可以查看当亲的栈信息

发现这个是可以截取我们的初始jdbcUrl，然后提取我们的classname参数，将反射的类设置成我们想要的org.springframework.context.support.ClassPathXmlApplicationContext

最后会调用到newInstance来让前面设置好的构造器新实例化一个对象

到后面就是ClassPathXmlApplicationContext类远程加载恶意xml，本人起初调试到这已经看不懂了，然后参考了下y0n3er的博客

ClassPathXmlApplicationContext的不出网利用学习 | Y0n3er’s Blog

看标题是不出网的，但是我们这里是要远程加载恶意的xml，实为出网利用…
