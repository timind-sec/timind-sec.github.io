域渗透学习随笔（一）

1、Kerberos协议以及在域中的鉴权机制

基本概念

相关术语解释如下：

  • Client： 访问服务的客户机
  • Server：提供服务的服务器
  • KDC(Key Distribution Center)：密钥分发中心，KDC由以下两个部分组成
    Authentication Service(AS)：身份验证服务
    Ticket Granting Service(TGS)：票据授予服务
  • Authentication Service(AS)：AS的作用是验证Client端的身份，验证通过之后，AS就会将TGT票据(Ticket Granting Ticket)给Client
  • Ticket-Granting Ticket(TGT)：TGT对象的ID为TGC的值，服务器端通过TGC查询TGT
  • Ticket Granting Service(TGS)：TGS的作用是用AS发送给Client的TGT换取访问Server端的ST(Server Ticket)给Client
  • Ticket-Granting Cookie(TGC)：TGC的作用是存放用户身份认证凭证的Cookie，在浏览器和CAS Server间通讯时使用，是CAS Server用来明确用户身份的凭证，TGT封装了TGC值以及此Cookie值对应的用户信息
  • Server Ticket(ST)：ST服务票据，由TGS服务发布
  • Active Directory(AD)：活动目录
  • Domain Controller(DC)：域控制器

网上博客翻到的kerberos认证的流程图，还是比较直观的

注意上图

  1. KDC是包括了AS和TGS两个服务，AS是用来接受域内主机（客户端）的第一次请求的，比如该主机想要访问域内的某个服务，需要向KDC中的AS发起请求，然后Kerberos校验通过之后就会返回一个TGT认购权证，整个过程就是AS-REQ到AS-REP
  2. 申请访问服务的时候，客户端需要拿着TGT向KDC的另外一个认证服务——TGS申请服务票据，这个过程就是TGS-REQ，然后相对应的TGS分发放普奥局的就是TGS-REP

黄金票据攻击和白银票据攻击的区别

（1）黄金票据攻击主要是利用了krbtgt的账户 hash，那么攻击者就可以伪造自己想要的TGT，然后再申请自己想要的ST服务票据，整个过程主要是利用了Kerberos认证过程中TGS-REQ的安全问题来进行TGT的伪造，同时呢，攻击者可以利用伪造的TGS去访问域内的任何服务在 Kerberos 协议中，TGT 是由 krbtgt 用户的 Hash 进行加密和签名的。只要你拥有了 krbtgt 的 Hash，你就相当于拥有了：

  1. 全知全能的签名权： 你可以伪造 TGT 里的任何信息，比如把自己的 SID 改成 **Domain Admin (512)**。
  2. 超长有效期： 默认 TGT 有效期通常是 10 小时，但伪造的黄金票据可以设置为 10 年甚至更久。
  3. 无视密码修改： 即使受害用户修改了密码，只要 krbtgt 的 Hash 没变，黄金票据依然有效。

（2）白银票据的威力在于它彻底跳过了 Kerberos 的前两个阶段，正常的流程应该是客户端向kdc申请TGT认购权证，然后再拿自己的TGT去向AS申请ST去访问域内服务，但白银票据攻击跳过了整个阶段，因为他利用了域内某个特定主机的hash并在本机上伪造ST，并拿着这个伪造的ST去访问该主机上的特定服务

同时，因为它不经过 KDC（域控上的 Key Distribution Center），所以域控的日志里甚至不会留下任何认证记录，隐蔽性极高。

由于白银票据利用的是目标服务账户的 Hash（通常是计算机账户，例如 DC01$），你只需要拿到这台机器的本地管理员权限并导出 Hash 即可。

常见的服务类型（Service Type）：

  • CIFS: 访问文件共享（SMB）。
  • HTTP: 访问 WinRM 或 Web 服务。
  • LDAP: 访问目录服务。
  • HOST: 允许通过计划任务（Scheduled Tasks）等方式执行命令。

2、SPN渗透以及Kerberoasting攻击

spn是什么

在之前我们对kerberos协议的学习过程中，我们发现有些主机在域中扮演了某一个特定服务的角色，也就是域中主机拿着ST去申请某个服务的权限，那么我们怎么识别这个服务呢，这里就提出了一个标识性的东西——spn。

SPN(ServicePrincipal Names)服务主体名称，是服务实例(比如：HTTP、SMB、MySQL等服务)的唯一标识符。Kerberos认证过程使用SPN将服务实例与服务登录账户相关联，如果想使用 Kerberos 协议来认证服务，那么必须正确配置SPN。

SPN 的核心作用，是为 Kerberos 这个域环境下的安全认证协议服务的。它的作用很像一个“中间人”或“翻译官”，把客户端想要访问的服务，和运行这个服务的域账号关联起来

具体过程可以分为几步：

  1. 客户端发起请求：当一台电脑（客户端）想访问另一台服务器上的服务（比如 SQL Server 数据库）时，它会告诉域控制器（KDC）：“我想访问 MSSQLSvc/sqlserver.domain.com 这个服务”
  2. KDC 查找“门牌号”：域控制器接到请求后，就会拿着这个“门牌号”（也就是 SPN）去 Active Directory 数据库里查，看它是注册在哪个具体的计算机或域用户账号名下的
  3. 关联账号并颁发“入场券”：找到关联的账号后，域控制器就会用这个账号的密码哈希，专门为客户端加密生成一张用于访问该服务的“入场券”（ST票据）
  4. 客户端凭“券”入场：客户端拿着这张“入场券”去找目标服务器。服务器用自己账号的密码哈希解密验证票据，如果通过，就允许客户端访问了
