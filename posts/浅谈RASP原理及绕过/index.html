1-前言

这几天有点沉浸在面经的海洋中了，无意之中看到了Z3r0佬提供的ct红队面经，里面就提到了一个非常熟悉但又陌生的概念——RASP防护，笔者遂浅学了一些关于RASP的工作原理及绕过方式，下面是本人学习笔记。【如有错误，还请纠正】

2-RASP介绍

【官方】RASP是一种安全技术，旨在通过在应用程序运行时实施保护机制来增强应用程序的安全性。它使得应用程序能够实时监控和防御潜在的攻击，而不依赖于外部的安全设备或控制措施。因为从 JDK 1.5 开始，Java 提供了一种动态代理机制，允许代理检测在 JVM 中运行的服务，通过插桩的方式修改方法的字节码，而 RASP 实际上就是通过 hook 系统的关键函数实现防护。

其实主要说白了就是，RASP他不同于平时我们所见的waf，常规的waf只针对于攻击者的直接攻击流量，也就是各个路由中添加一道利用提前写好各种规则的防火墙，然而这种只判断直接流量的机制，如今却容易被攻击者精心构造的各种编码、混淆的payload绕过，所以就有了这么一个防御机制：RASP，它通过javaagent机制，随时跟踪攻击者的行为，比如：用户输入直接拼进 SQL → 拦截，是合法参数拼进 SQL →，那么就放行；

所以相比于waf，RASP更能区分 “真攻击” 和 “正常业务”，误报极低。

那么RASP是怎么实现对系统的hook的，以下为两种常见的hook方式：

2-1-java Agent

Java Agent 是一种特定于 Java 编程语言的工具，用于在 Java 虚拟机（JVM）启动时或运行中对 Java 应用程序进行监控、修改和增强。Java Agent 的功能主要依赖于 Java Instrumentation API，该 API 允许开发人员在字节码级别对 Java 类进行操作和修改。

通过java agent技术进行类的字节码修改最主要使用的就是Java Instrumentation API

2-2-Java Agent 的使用场景

  1. 性能监控：通过跟踪方法调用、执行时间和资源使用情况，提高应用程序的性能分析能力。
  2. 安全性增强：在方法调用过程中插入安全检查，确保访问控制和输入验证。
  3. 日志记录和审计：自动捕捉方法入口、出口和异常信息，减少显式日志记录的需求。
  4. 测试与调试：为测试工具提供支持，允许自定义行为的动态插入。
  5. 静态分析：在类被加载时进行静态分析，提供编译时无法发现的错误和警告。

2-2-Attach机制

2-2-1 Attach是什么？

Attach机制相当于动态加载agent程序，即热加载，无需重启jvm，即可当JavaAgent注入时，动态的修改字节码。上面所写的Premain方法还得在jvm启动前挂在agent，这既是Attach一大优势。

2-2-2 Attach实现原理

Java 进程启动时，JVM 自动创建 Attach Listener 线程，创建本地通信文件，阻塞等待外部连接，不占用业务线程资源。

客户端程序通过进程 PID，调用VirtualMachine.attach(pid)发起连接：

  • 客户端创建套接字客户端，连接目标 JVM 监听端口
  • 校验进程归属、权限，建立通信通道

连接成功后，客户端发送固定协议指令：指定 Agent jar 路径、启动参数，请求 JVM 加载代理。

Attach Listener 捕获指令后，发起安全点停顿：

让所有业务线程运行到安全位置暂停执行，避免字节码修改时线程并发读写引发异常。

JVM 读取指定 jar 包，识别MANIFEST.MF中Agent-Class配置，实例化代理类，调用agentmain方法，同时传入 Instrumentation 实例。

在 agentmain 中调用inst.addTransformer()注册自定义ClassFileTransformer，绑定字节码修改逻辑。

调用inst.retransformClasses(Class<?>... classes)：

  1. 取出 JVM 方法区中已存在的原始字节码
  2. 交给注册的转换器做 ASM 等字节码编辑
  3. 将新字节码替换原有 Class 定义

字节码替换完成，退出安全点，唤醒所有业务线程。后续调用类方法，都会执行修改后的字节码逻辑。

指令执行完毕，客户端与 JVM 断开套接字连接，Attach Listener 回归监听状态。

3-RASP绕过

RASP能获取到最后Sink函数的执行点，所以不管多么底层的业务逻辑，只要是RASP涉及到的，不管怎么编码绕过，都会被拦截，查找文章发现，绕过方式主要有两种

  1. 寻找没被限制的类或者函数进行绕过，即黑名单绕过
  2. 利用更底层的技术进行绕过如C代码

3-1-JNI绕过

JNI 是本地编程接口（java native interface），它使得在 Java 虚拟机（VM）内部运行的 Java 代码能够与用 C、C++、汇编等其他语言编写的应用程序和库进行互操作（interoperate）。

其实主要是java开发的过程中，java语言还是需要C，C++代码等这样的底层代码来实现，这里仅以C代码进行探讨。JNI这种机制的设计就是让java能调用C程序，这个C程序并不是C代码生成出来的exe，而是编译成dll动态链接库。
